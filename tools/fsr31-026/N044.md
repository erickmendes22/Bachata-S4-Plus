# n044 — correct the changed depth-candidate rule from n043

48DCA539 is a real failure (userRequestedStop=false). The guest logs DLRegularHeap.cpp(710), an invalid/already freed block, then intentionally panics with SIGSEGV at guest eboot+0x20b56d2. This is before any temporal context-ready or AMD dispatch marker. n042 FF1A56D6 records a real dispatch; n043 records zero. The 266 applied patch writes are identical in both sessions and the native core/Dex/patch payload remains unchanged.

The new n043 rule interpreted DEPTH_STENCIL read/write access mask 0x600 as an executed overwrite. It repeatedly retired local depth candidates in this session, blocking the temporal path. A synchronization access declaration does not prove an executed write. n044 removes that false rejection and retires depth only on the observed vkCmdClearDepthStencilImage operation. The same-CB color-write protection and its cyan negative control remain.

GPU tests cover the exact 0x600 read-only depth transition: the scene must remain eligible and reach real AMD reconstruction. A real depth clear must retire it. Existing temporal, cross-CB, owned UI, abandoned recording and cyan tests are required. No replacement core, patch changes, guest-heap panic bypass, or new RGB workaround.

This corrects a demonstrated SDK regression; the log alone does not establish that this metadata rejection caused the guest heap panic. Device crash resolution remains unverified.
