## Concrete corrections

The movie boundary was inferred from the last vertex push-constant layout. Compatible pipeline changes do not require updating those constants. That can authorize pre-HUD FSR with a scene shader bound. Track successfully created graphics pipelines and their layouts, intercept actual GRAPHICS binds, and use that identity for movie classification, draw provenance and native UI state. COMPUTE work/restoration does not replace graphics identity. Unknown bound graphics pipelines fail closed. Tests explicitly switch a scene pipeline after stale movie push constants and require rejection; switching back to a known movie pipeline must succeed.

WSI sampling previously applied its event throttle before looking for an already selected CB. A later writer could be skipped, leaving old pixels in the sample. Update selected samples after every intercepted writer in that CB, independently of selection throttle; order repeated copies into a single readback slice with a transfer WAW dependency. Tests use eight yellow writes followed by a cyan ninth write in BGRA8. The corrected sampler must report cyan; the host-only old-behavior control must report yellow despite the actual image ending cyan.

Once the original command buffer has been successfully submitted, mark its sampling slot submitted before attempting to create/submit the completion marker. A fence-create failure quarantines its memory, rather than leaving it eligible for reset as an unsubmitted recording. This addresses an error-path use-after-free; EE1BA5C5 does not record that fence failure, so it is not a confirmed cause of that device session.

Each WSI write now has a serial. The final-write ledger advances in actual successful submit order (including both VkSubmitInfo versions), independently of temporal scene eligibility. Associate completed samples with the actual presentation sequence, image index and result. Mark final_write_matched only when that sample's recorded writer equals the submitted final writer of the presented image. Retain pending samples until a presentation tag exists; never equate a capture counter to a presentation counter. Include coordinates and raw bytes for nine specific pixels, and emit a single bounded log record to prevent event fields interleaving across threads.

## EE1BA5C5 evidence and limits

The report shows real BGRA8 WSI sampling and saturated native/pre-HUD/post-HUD/WSI sample values. It does not correlate those earlier samples to the exact displayed cyan screenshot, and a submitted sample's fence alone does not prove it contains the last write to that image. Termination is CANCELLED_BY_USER. Earlier zero-cyan readings cannot conclusively exclude a cyan final frame: the regression test reproduces exactly that diagnostic blind spot.

The bound-pipeline correction removes an objectively invalid FSR activation condition. Neither static inspection nor synthetic GPU tests prove that it caused every phone cyan frame. Device elimination of cyan remains unverified. Core025, SDK temporal dispatch, camera/depth contract and Android payload are retained. Full production same-target RunScaled/owned-HUD parity and object motion/reactive masks are still separate integration gaps.
