# n043 — preserve the actual last writer of the temporal scene

Source baseline: n042 cd5681c22ae0a5a610e410470414f338f3392725. FF1A56D6 confirms n042 and real temporal dispatch while cyan/white corruption persists; matching color/depth allocations is insufficient proof of final scene contents. Manual stop is not evidence of a crash.

The n042 invalidator only considered a globally submitted candidate. A local ScenePass remained ready after later compute/transfer writes inside the same CB and was published again on submission. It also missed generic SHADER_WRITE and broad MEMORY_WRITE with writable layouts. Retire matching local and submitted color/depth candidates; SDK-owned transitions are exempt. A later legitimate scene rendering pass can establish a fresh candidate.

GPU regression: completed blue 640x360 LDR is overwritten with cyan before the native HUD pass. The old path feeds the stale candidate to AMD and produces cyan beneath an intact HUD. The corrected path preserves the original native background/HUD. This is a reproduced mechanism, not proof that the phone flash has no other cause.

Restore the native compute-state module omitted from the n042 source branch; keep n042 fences, layout ledger, camera cuts and backing checks. No emulator core compilation, no new Scheduler hook, no RGB clamp or format workaround.

Packaging uses the retained unchanged Android/core payload of n040 (same 562 runtime files and c1cf... core025) with the SDK compiled from the n042 code baseline plus these fixes. The exact n042 APK was linked from another transient /mnt/data environment and is not present in this workspace or current Library inventory. No claim of byte-for-byte equivalence to that absent APK; core025, DEX, patches and all other retained payloads are verified against the materialized n040. Runtime n043 forces re-extraction.

Additional regression checks: owned UI image aliases now query this CB's layout ledger, not the previous globally submitted layout. Abandoning a recorded SDK dispatch invalidates CPU-side FFX history/layout predictions and requires a safe drained rebuild; other unsubmitted owners continue blocking rebuild. Neither test failure is treated as proof of the phone flash.
