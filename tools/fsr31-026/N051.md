## Rendering correction

The n050 identity fix used the currently bound Vulkan graphics pipeline at BeginRendering. Native renderer ordering is BindResources/complete 120-byte graphics PushData, dynamic state, BeginRendering, then vkCmdBindPipeline and draw. At the boundary, the bound graphics pipeline can still be the preceding draw. This both rejects upcoming HUD and can accept a scene following HUD. Use fresh upcoming resources at the pre-render boundary, and actual bound pipeline for executed draw provenance. A real graphics bind or draw consumes the pending packet; compute binds do not. Unknown actual pipelines still fail closed once pending resources have been consumed. No scheduler insertion, pass interruption, color inversion, guessed brightness clamp or Presenter downsample.

CPU regression exercises both transition directions, compute in-between, consumption, stale constants and unknown binds. A host-only negative control restores n050 boundary behavior and must fail the upcoming-HUD assertion. It is absent from ARM release.

## Capture correction

Use a separate bounded cadence per swapchain image instead of the global 64-event cadence. Selected CBs still refresh after every writer. WSI force-selection bypasses the temporal probe's independent frame%16 policy. A headless GPU regression cycles four separately allocated BGRA images for 260 submissions and requires final-writer-matched probes for all four at sequences257..260; image2 is cyan. Remove cadence/final-writer metadata on image/swapchain destruction, while retaining fence-owned in-flight readback memory.

## Remaining evidence limits

These changes correct established ordering and measurement defects. They do not establish that either defect explains all cyan observed on the phone. The current production path still differs from the Port's same-LDR-target RunScaled contract and object-motion/reactive-mask path. Synthetic GPU tests are not proof of production owned-HUD wiring or all-frame temporal coverage. Cyan elimination on the physical device remains unverified.

## Logging requested after report upload

GPU_FRAME_PROBE emits exact top-left, center and bottom-right pixels (decoded values plus raw RGBA/half bytes) for native input, owned clone, AMD output, pre-HUD composite and post-HUD image in the same completed temporal slot. It records image handles, dimensions and recording CB. WSI probes retain nine exact BGRA/RGBA coordinates and final-write/present matching. WSI_WRITE_SOURCES records actual presenter shader hashes and sampled image handles/formats/dimensions/layouts for selected samples, using provenance only when the writer belongs to that CB. Unknown provenance and unresolved temporal association are explicit rather than inferred from nearby timestamps. The original 64-event selection bias and temporal frame%16 rejection of independent WSI samples are removed. Records use bounded one-write formatting. These logs can localize a channel discrepancy or wrong input; they do not promise an automatic root cause or fabricate a same-frame FSR association.
