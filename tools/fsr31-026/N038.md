# n038 — temporal resources follow GPU completion

Base APK: exact n037 P36; same core025 binary as n036. Replace only independently built `host/libbachata_fsr31.so` and runtime extraction identity. Keep n037 compute-state restoration and direct/indirect jitter. No native core compilation or Scheduler hook.

DF9D2DA8 reports real temporal dispatch on Adreno 830, but the user confirms blue flicker persists. The report does not identify its cause. The following defects were found and reproduced independently:

* Updating the motion descriptor again on ring wrap invalidates an earlier executable command buffer using that set, even when the descriptor contents are unchanged. Initialize each set once per GPU-drained context instead.
* Four surface slots previously wrapped without GPU completion proof. Track recorded owners, attach a private completion fence with an empty submission after the caller's original submission, and wait only on the reused slot. Preserve original wait/signal lists and caller-owned fence. Both Submit1 and Submit2 are supported. An unsubmitted slot declines before SDK commands; it cannot be waited on. The bounded GPU wait declines on timeout.
* Do not rebuild a context while any other temporal command buffer is still recorded and unsubmitted. Reset/discard cancels that owner; rebuild after a GPU drain once all remaining owners are submitted or discarded.
* Reset AMD temporal history after a gap in actual temporal camera-frame dispatches. CPU Presenter callbacks are not completion proofs.

Validation: Vulkan queued-command-buffer regression records four FSR command buffers before submitting them, checks safe refusal of a fifth unsubmitted-slot reuse, then repeats with completed slots and checks final image pixels. Host-only negative control restores old descriptor mutation and unsafe wrap; it reproduces command-buffer invalidation. Production ARM64 excludes all negative-control switches. Existing AMD, compute restoration, same-target HUD, cross-CB and UI preservation tests remain required.

Periodic dispatch telemetry includes actual temporal frame count, camera frame, reset and jitter every 600 dispatches. The changes address real resource-lifetime faults; elimination of blue flicker and performance stalls on Adreno is not yet verified. No claim that every presented frame uses FSR.
